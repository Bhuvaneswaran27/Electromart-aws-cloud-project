# ElectroMart – AWS Cloud E-Commerce Backend

ElectroMart is a cloud-based e-commerce backend application built using
Node.js, Express.js, MySQL, Docker, and Amazon Web Services (AWS).

The application is containerized using Docker and deployed on Amazon ECS
Fargate. A CI/CD pipeline using GitHub, AWS CodePipeline, and AWS CodeBuild
automates the build and deployment process.

## Project Overview

ElectroMart provides REST APIs for managing products and e-commerce
operations. The application connects to Amazon RDS for database storage
and is exposed through an Application Load Balancer.

The Docker image is stored in Amazon ECR and deployed to Amazon ECS Fargate.

## AWS Infrastructure
### Amazon ECS Fargate

Runs the containerized ElectroMart application without requiring
management of EC2 instances for the application containers.

### Amazon ECR

Stores the Docker image generated by AWS CodeBuild.

Example image:
```text
610213206510.dkr.ecr.ap-south-1.amazonaws.com/electromart:latest
```

### Amazon RDS

MySQL database used for persistent application data.

### Application Load Balancer

Distributes incoming HTTP traffic to the ECS service.

### Amazon CloudWatch

Used for application logs and monitoring.

### AWS CodeBuild

Builds the Docker image and pushes it to Amazon ECR.

### AWS CodePipeline

Automates the CI/CD workflow from GitHub through the build and deployment
stages.

## Security

The project uses AWS IAM and Security Groups to control access to AWS
resources and network traffic.

Database credentials should be supplied through environment variables or
AWS Secrets Manager rather than hard-coded in application source code.

Sensitive files such as .env are excluded using .gitignore.

### Challenges & Solutions
### 1. CodeConnections Permission Error

The GitHub connection initially failed because the IAM identity did not
have permission to perform:
```text
codeconnections:StartOAuthHandshake
```
The required IAM permissions were granted to establish the GitHub
connection.

### 2. ECR Authorization Error

CodeBuild initially failed because its service role did not have permission
to perform:
```text
ecr:GetAuthorizationToken
```
The required ECR permissions were added to the CodeBuild service role.

### 3. Dockerfile Not Found

CodeBuild initially reported:
```text
failed to read dockerfile:
open Dockerfile: no such file or directory
```
The repository was corrected so that the Dockerfile was available in the
project root.

### 4. Application Load Balancer

The ECS service was configured with an Application Load Balancer and a
target group. The ECS task was successfully registered as a healthy target.
